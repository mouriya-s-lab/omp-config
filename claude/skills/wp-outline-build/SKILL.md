# 大纲

## 这个阶段解决什么问题

把选题阶段确定的角度和形态，展开为一个完整的逻辑骨架——读者从开头到结尾的思维路径。

输入：素材 + `topic-selection.md`
产出：`outline.md`

## 约束

大纲必须在选题确定的形态和角度范围内展开。如果大纲过程中发现选题有问题，回阶段一修改选题。

---

## 关键动作 1：读者画像定义

**做什么**：用三个维度精确定义目标读者。

三个维度：
- **知识边界**：读者已经知道什么概念？哪些术语可以直接使用不需要解释？哪些必须在首次出现时给一句话定义？
- **阅读动机**：读者为什么会点开这篇文章？他带着什么问题、什么困惑、什么期待来的？
- **预期收获**：读者读完后应该能做什么他之前做不到的事？能解释什么他之前解释不了的现象？能做出什么他之前犹豫的决策？

**做到什么程度**：三个维度各一两句话。每个维度的定义必须足够具体，能指导后续"该不该展开这个点"的决策。

**反例**：
- "目标读者是技术人员" → 太模糊，无法指导任何决策
- "目标读者是用过 TypeScript 的 discriminated union 但没系统想过全栈类型链的前端开发者" → 够具体，能判断哪些概念需要解释

---

## 关键动作 2：核心论点锻造

**做什么**：用一句话写出文章的核心论点。

**标准**：
- 必须是一个可以被同意或反对的判断，不是一个话题描述
- "AI 对 SaaS 行业的影响" → 话题描述，不是论点
- "SaaS 公司的生死取决于它的核心功能是确定性的还是概率性的" → 论点

**做到什么程度**：一句话。如果写不出一句话的论点，说明还没想清楚要说什么——回选题阶段。

---

## 关键动作 3：逻辑线构建

**做什么**：构建读者从"不知道/不相信"到"理解/被说服"的推理路径。

**操作**：
1. 从核心论点出发倒推：读者要接受这个论点，需要先接受哪些前提？
2. 这些前提之间的逻辑顺序是什么？用连接词测试：
   - A **因为** B → 因果链
   - A **但是** B → 对比/转折链
   - A **而且** B → 递进链
   - A **就像** B → 类比链
3. 每个前提靠什么支撑？标注论据类型：
   - 数据（具体数字、统计）
   - 案例（具体的事件、公司、人）
   - 引用（专家原话、研究结论）
   - 推理（逻辑演绎）
   - 类比（和读者已知事物的对比）
4. 支撑不足的前提标记出来：要么 deep research 补全，要么弱化这个前提

**做到什么程度**：能画出一条从开头到结尾的逻辑链，每一步的连接词和支撑论据都标注清楚。

**多源文档特别注意**：如果素材来自多份文档，文档之间的关系必须是逻辑性的（因果、对比、互补），不能只是按时间线或按文档顺序排列。问自己：文档 A 的内容和文档 B 的内容之间的逻辑关系是什么？

---

## 关键动作 4：读者追问链

**做什么**：模拟读者读完每个段落后脑中自然冒出的问题，确保下一段回答的就是那个问题。

**格式**：
```
开头段：提出 [核心判断]
  → 读者追问："凭什么这么说？"
第二段：给出 [第一个论据]
  → 读者追问："这在实际中是怎么体现的？"
第三段：展开 [具体案例]
  → 读者追问："那反面呢？有没有不成立的情况？"
第四段：讨论 [边界条件/反例]
  → ...
```

**做到什么程度**：画不出追问链 = 逻辑线没想清楚。每一步的追问必须是这个读者画像会自然产生的问题，不是写作者想讨论的问题。

---

## 关键动作 5：结构选择

**做什么**：基于逻辑线的形状，选择文章的组织结构。

**逻辑线形状 → 结构映射**：
- 线性因果链（A导致B导致C） → 问题驱动 / SCQA
- 多条平行分支（A、B、C 共享主题 D） → 多中心结构
- 有时间维度（事件按时间发展） → 时间线 / 混合式
- 有对比关系（A vs B） → 平行叙事
- 有强烈的戏剧性切入点 → 环形结构

**做到什么程度**：选定结构 + 一句话说明为什么逻辑线匹配这个结构。

---

## 关键动作 6：节奏设计

**做什么**：标注每个段落的展开密度。

**三种密度**：
- **慢镜头**：核心论点的支撑段。展开细节、还原场景、给完整案例、展示推理过程。读者在这里获得最多的理解。
- **快进**：过渡和铺垫。一两句话带过，连接两个慢镜头段落。
- **金币**：读者可能走神的位置放一个奖励——意外的事实、生动的类比、尖锐的判断、有画面感的场景。

**做到什么程度**：大纲中每个段落旁边标注"慢/快/金币"。一篇全是慢镜头的文章拖沓，全是快进的像摘要，没有金币的中段会掉读者。

---

## 关键动作 7：标题与承诺

**做什么**：拟工作标题。

**标准**：
- 标题必须暗示一个具体的承诺——读者看到标题后会期待什么？
- 期待的东西在大纲中有对应的段落兑现吗？
- 如果标题是个问题，大纲中有回答吗？

**做到什么程度**：标题 + 一句话"读者看到这个标题会期待 ___" + 确认"大纲中的 ___ 段落兑现了这个期待"。

---

## 关键动作 8：对抗检验

**做什么**：从读者视角对抗检验大纲。

**怎么做**：用 subagent 或自我对抗，模拟读者画像中定义的那个读者：

1. **逻辑链检验**：每一步之间的连接词说得通吗？有跳步吗？
2. **追问链检验**：下一段是否回答了上一段引发的自然追问？有没有"为什么突然说这个"的跳跃？
3. **支撑检验**：每个论点的支撑够吗？如果只看论据不看论点，能反推出论点吗？
4. **承诺检验**：标题的承诺在大纲中有兑现吗？
5. **结构检验**：结构是否匹配逻辑线的形状？有没有把应该按逻辑关系组织的内容按时间线排列了？

**对抗规则**：挑战方只看大纲不看素材原文——大纲本身逻辑不自洽说明还没想清楚。

**不通过就不进阶段三。** 回去修大纲。

---

## 产出：`outline.md`

文件内容：
1. 读者画像（知识边界、阅读动机、预期收获）
2. 核心论点（一句话）
3. 逻辑线（前提链 + 每步的连接词 + 论据标注）
4. 读者追问链
5. 结构选择及理由
6. 带节奏标注的段落大纲
7. 标题 + 承诺 + 兑现确认
8. 对抗检验结果（通过/不通过 + 修改记录）

# child body 区块与 child 类型

什么时候读我：写 child body、选 child 类型、定 parent 归属时。

## 区块（按序）

**## 必须先读的关联 issue** — 回答「我继承了什么」。写：umbrella 编号 + 所继承契约条款的**逐字快照**。自包含优先于 DRY：headless 读者不做跨 issue 图遍历。

**## 目标** — 一句话，这个 child 解决的那一个问题。目标必须可追溯到方向原文、契约条款、或 repo 既有承诺（README / 设计文档 / 历史决策）。失败模式：**进口目标**——三处都追溯不到的目标（典型：给内网工具自带「应该有鉴权 / 加密 / 配额」）是作者价值观不是任务，安全姿态、运维取舍属操作员独有事实，按 decision-closure.md 的回传边界处理（回传或显式假设），不直接立 child。

**## 使用场景** — 回答「落地后用户/系统观察到什么使用形态」。业务层在 child 上的家：没有 CLI/UI 触感的基座 child 也要明说「只为后续 child 提供基座」。与「预期结果」的分工：这里写场景叙事，那里写可验证性质。

**## 上下文** — 回答「已知事实钉在哪」。写：repo、design source、baseline 锚点——**概念锚点**（文件 + 符号 + 当前行为描述）并标注「实施前自行 grep 核对行号」。行号会漂而符号和行为不会；照搬旧行号的代价是 agent 在错误位置动手。repo 不可达或指称未解析（SKILL.md「方向解析」）时不编造路径——写「unknown + 定位步骤」，定位与事实建立由 audit child 承载，本区引用其登记表条目；编造的锚点比缺失更糟，headless agent 会在虚构位置动手。

**## 问题** — 回答「现状为什么不满足目标」。写：可观察的问题 + 引用（代码行、历史决策原文、运行证据）。失败模式：在这里写改法——问题陈述被方案预设污染后，「预期结果」和「验收」全会被这个预设牵引；改法的位置在决策层（裁决后写入）或 PR。

**## 预期结果** — 回答「完成后观察到什么」。**用性质表述，不用机制枚举**，例如「agent 可达的一切 X 路径都经 Y 校验」；性质定义覆盖范围，不能仅凭措辞就认定旁路已被封住。配套写明实际保证机制、适用边界及真实路径验收。遵循全局 functional/ADT 偏好：语言与项目模型支持时优先用领域类型、受限构造和编译器穷尽检查；否则按项目惯例说明边界解析、运行时校验或协议约束如何保证性质。不把品牌类型或特定 union 写成通用硬要求，也不用 typecheck 替代 runtime 证据。

**## 不应残留** — 两半：本 child 范围内不许留下的（旧路径、兜底、字面量）；**本 issue 范围之外不应改动的**（防顺手越界）。

**## 约束** — 只写外部强加的硬约束（继承自契约 + 本 child 独有）。失败模式：把偏好包装成约束——headless agent 无法区分「违反会坏」和「作者喜欢」，真约束被稀释。

**## 验收标准** — 使用 `skill://writing-issue` 的 checkpoint 契约（Dimension / Check / Command / Env / Expect）：每条预期结果都有真实路径直接观察它的覆盖行，Check 点名；卫生检查及实现者本次自写测试不能承担结果覆盖。模拟最省事路径，确认目标未达成时表不能全绿。维度覆盖实际的 function / environment / integration / assumption 风险。

**## 继承验证义务**（如有）— 沿用 checkpoint 表，加 From / Original #，指明 owner；上游移交的义务不可二次延期。

**## 依赖关系** — Depends on / Blocks，写明需要上游的什么后置条件。语义上「无依赖」不等于可并行：物理共面（本 child 与哪些 siblings 改同一文件）由 umbrella「依赖图与编排」区块裁定，写「无」前先对照该区块。

## child 类型（默认是实现 child，另有三种）

- **audit child（调查即 issue）**：当清点本身需要 headless 执行或体量配得上独立工件时，调查不内联在写作里、立成 issue。产出 = **应然/实然/证据**登记表（每行：契约应然 + 现在的行为 + `file:line` 证据）。登记表不混方案——混入的代价是事实与判断失去分离，后续 child 引用事实时被迫连带继承未经裁决的方案；怎么改由各实现 child 承载。audit 可以充当树根：body 装登记表（事实），契约/设计落它的 comment 层，实现 children 从「设计 comment §N」逐字快照继承。登记表条目编号一经引用即**稳定**：范围更正移出条目时保留编号并写明去向——重编号会让 children 对「条目#N」的引用静默断裂。
- **spike child**：高风险假设的前置验证，「未决设计问题」区块的解决方多为此类。触发：实现依赖未文档化的第三方行为、跨网络/跨环境连通性、或「should work / expected to / presumably」式推测语言。形态：标题 `Spike: <验证的那一个假设>`；区块集 = 标准区块以「假设原文（带来源引用）」替代「问题」、以「验证步骤 + 结果分支」替代「预期结果」，保留：必须先读、目标、上下文、不应残留（产出是证据不是生产代码）、验收标准（assumption 维度，具体命令 + 目标环境 + 期望）、依赖关系；可省：使用场景。不钉死区块集的代价：每棵树的 spike 各长一形，审查无模板可对照。**结果分支**——passed → 进实现 issue；failed → 带证据开 design-question，**不进实现**；`Blocks: #<依赖该假设的实现 issue>`。失败模式：把 spike 写成小号实现（产出应是证据与结论，不是生产代码）；验证步骤不可跑（没有环境就先解决环境或显式移交，不留无主的延期验证）。
- **收尾对齐 child**：文档/登记/定性向修复后实态对齐，gate 在全部结构性 children 之后。文档 drift 是一等偏离；计数类内容改为**从代码派生 + 测试守护**——手写计数必然再 drift。

## parent 归属

child 的 parent 由**问题的性质**决定，不由发现路径决定：契约债挂债务 umbrella，回归是独立 bug 不挂；审查中发现某 child 性质不符，移出树并留更正记录（移出 ≠ 删除，引用保持可解析）。

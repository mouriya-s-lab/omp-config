# ssh-mcp-sync

`sync.py` regenerates a managed block in `~/.ssh-manager/.env` for `mcp-ssh-manager`. Use `iac-projects` for inventory ownership and `iac-issue-routing` if reconciliation exposes an infrastructure change. This helper updates local connection configuration; it does not provision hosts or repair MCP installation.

## Source mapping

| Source | Rendered connection |
|---|---|
| `homelab-tf/{apps,browser,moat,paas,trading,workstation}/vms/*.yaml` | `hostname:` becomes `<hostname>.hb.lan`; filename supplies VMID for the description |
| `pve-vctcn/apps/*/main.tf` | Literal hostname in `module "vm_<id>"` becomes `<hostname>.mouriya.lan` |
| `static_hosts()` | `PVE` at `pve.hb.lan`; `VCTCNPVE` at `192.99.9.212` |

Only those source shapes are parsed, not arbitrary Terraform expressions or newly added workspace families. Missing source directories are skipped; missing hostnames and duplicate normalized keys produce warnings. Do not accept a large removal diff until checkout paths, parsed declarations, and warnings are understood.

CTs are excluded: the homelab deployment path uses PVE SSH plus `pct exec`, not CT-side sshd. Inventory-only SSH hosts such as `omv`/`dockge` are also excluded unless separately TF-declared. Put intentional external/manual connections outside the managed block; discovering an inventory-only host does not make it managed.

Keys are uppercase with all non-alphanumeric characters removed: `agent-runtime` becomes `AGENTRUNTIME`, `vctcn-registry` becomes `VCTCNREGISTRY`. The MCP server identifier comes from the part between `SSH_SERVER_` and `_HOST`; inspect the generated configuration rather than inventing a hyphenated alias.

## Preservation boundary

Markers are exact:

```text
# === BEGIN ssh-mcp-sync managed (regenerated by ~/.claude/skills/ssh-mcp-sync) ===
# === END ssh-mcp-sync managed ===
```

- With both markers present, their enclosed block is replaced; text outside is preserved verbatim.
- Without a complete marker pair, the first-run path removes **every** existing `SSH_SERVER_*` line, including manual connections. Other lines become a manual tail. Preserve required manual server definitions separately before applying that migration, then place them below END. Do not mistake the first-run tail for preservation of old server entries.
- Managed per-server `KEYPATH`, `PROXYJUMP`, or `PLATFORM` overrides are not part of the renderer. If needed, extend the helper from authoritative IaC fields as a separate code change, not a CT-side/config patch that regeneration erases.

## Run and interpret

```bash
# Local diff only: no SSH and no configuration write.
python3 ~/.claude/skills/ssh-mcp-sync/sync.py

# Always probe the discovered entries; no .env write.
python3 ~/.claude/skills/ssh-mcp-sync/sync.py --verify

# If there is a diff, probe and refuse to write on any failure.
python3 ~/.claude/skills/ssh-mcp-sync/sync.py --apply
```

1. Inspect the dry-run diff. Additions/removals must match current IaC, not missing checkouts or a parser mismatch. Confirm manual-state handling before first apply.
2. Apply the reconciled change. Probe failures return nonzero and leave `.env` unchanged. A successful write reports `wrote <path>`.
3. Use `--verify` when connection health is the goal: **`--apply` returns `no changes` before probing when the file already matches**. A no-op apply is not reachability evidence.
4. The MCP reads the new file on its next process start. Verify the intended server through the actual MCP after restart; changing `.env` does not fix a missing executable or bad MCP registration.

Probes run `ssh ... true` in parallel with `BatchMode=yes`, `ConnectTimeout=8`, `StrictHostKeyChecking=accept-new`, `ServerAliveInterval=0`, and the entry's port/user. They inherit shell SSH configuration and `SSH_AUTH_SOCK`; no identity file is hardcoded. `accept-new` can write first-contact host keys to `known_hosts` even in `--verify` mode. Changed keys still fail. Success proves a real noninteractive login, not which credential source SSH selected.

| Failure | Recovery |
|---|---|
| Missing/renamed declaration | Confirm the intended inventory and correct the owning IaC source through its workflow; rerun reconciliation. |
| Confirmed decommissioning | Remove the declaration only through the owning IaC workflow, then rerun reconciliation; a failed SSH probe alone is not decommission evidence. |
| Temporarily stopped/rebooting/unreachable host | Wait or follow authorized host recovery; retain valid IaC rather than deleting it to pass a probe. The default apply still refuses to write. |
| DNS/timeout | Check LAN access for `.hb.lan`, mesh access for `.mouriya.lan`, then use `dns-check` where applicable. |
| `Permission denied (publickey)` | Inspect loaded SSH agent and authorized connection setup; never request a pasted private key. |
| Host-key failure | Verify the host identity/rebuild through authoritative records before changing trust. |
| MCP process will not start | Inspect installation/registration separately; this skill only reconciles server entries. |

Explicit exceptions, only after reviewing why verification cannot pass:

```bash
# Intentionally register an unreachable host; reports failures but writes.
python3 ~/.claude/skills/ssh-mcp-sync/sync.py --apply --tolerate-failures

# Emergency/offline configuration change; no connectivity evidence.
python3 ~/.claude/skills/ssh-mcp-sync/sync.py --apply --skip-verify
```

## Alternate checkout / config locations

| Environment variable | Default |
|---|---|
| `HOMELAB_TF_DIR` | `~/Ext/code/homelab-tf` |
| `PVE_VCTCN_DIR` | `~/Ext/code/pve-vctcn` |
| `SSH_MANAGER_ENV` | `~/.ssh-manager/.env` |

These also allow isolated fixture-based checks of rendering/splicing without touching the live MCP configuration. Such checks do not prove live SSH reachability.
